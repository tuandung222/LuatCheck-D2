\hdr{Short-term context.} Each run keeps one message list: the domain system prompt, the question (and any pasted document) wrapped as untrusted input, then alternating action and observation turns. Observations are compacted: a search returns the best-matching clauses of each record with a truncation flag, a repeated query or read returns a short notice, and budget notices tell the model when to answer or refuse. The controller has an 8,192-token context window. A case ledger records queries, retrieved ids, repairs, token counts and times.

\hdr{Long-term memory (implemented, not used in any run of this report).} Verified answers can be stored in a local database after the verification gate. Reuse requires a matching index version and a question similarity of at least 0.85, and the reused answer is re-verified. Memory is off in every run of this report and in the demo, so trials stay independent; matching sees only the question and not the facts that decide a case. A fixed set of patterns screens for personal data before a write.

\hdr{Knowledge sources.} Both corpora were built from public PDFs by text extraction, Unicode normalisation and segmentation at section headings. Each record carries its source URL, file hash and page numbers, and the retrieval unit is a record (an article or a clause). The HCMUT corpus has 10 documents and 143 records; five documents are amendment-only and the image-only base regulations are absent, and printed decision numbers come from a web listing. The labour corpus has 10 documents and 458 records; Decree 145/2020 and unnumbered annexes are absent, texts are as promulgated and later amendments are unchecked. Neither corpus has been reviewed by an external legal or academic-affairs specialist.

\hdr{Retrieval and reranking.} The index is built in memory at start-up. BM25 over title and content and TF-IDF over word 1--3-grams are fused by RRF. The top 20 candidates are rescored by a cross-encoder reranker (a Vietnamese reranker model); records longer than one window are split into overlapping windows of about 1,500 characters and the record keeps its best window. The first search of a run always uses the user's own question together with the model's query. Dense embedding retrieval with a stored vector index is implemented but not evaluated; it is a planned ablation. The reranker runs in a compact (GGUF) format on the Mac and in half precision on the GPU server. In a parity probe on 100 benchmark questions, the Mac runtime had a mean per-question Spearman correlation of 0.9994 with the fp32 reference and the same top-1 record in 99 of 100 questions (0.9943 and 100 of 100 for the GPU runtime), so accuracy (GPU) and latency (Mac) describe the same ranking behaviour; we still report them separately.
