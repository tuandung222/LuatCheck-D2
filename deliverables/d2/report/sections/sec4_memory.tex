\hdr{Short-term context.} Each run maintains a single message list: the domain system prompt, the user question (and any pasted document) wrapped as untrusted input, followed by alternating action and observation turns. Tool observations are compacted: a search returns the best-matching clauses of each record with a truncation flag, a repeated query or document read returns a brief notice, and step-budget notices prompt the controller to conclude with an answer or refusal before reaching the step limit. The controller uses an 8,192-token context window, and a case ledger records queries, retrieved IDs, repairs, token counts, and latencies.

\hdr{Long-term memory (implemented, disabled in all benchmark runs).} Verified answers can be stored in a local SQLite database after passing the verification gate. Reuse requires a matching index version and a question similarity of at least 0.85, and any retrieved answer is re-verified before return. Long-term memory is disabled across all benchmark runs and in the live demo so that trials remain independent and cached answers cannot ignore case-specific facts. Before any database write, regex filters screen out personal identifiers.

\hdr{Knowledge sources.} Both corpora were built from public PDFs by text extraction, Unicode NFC normalisation, and segmentation at article or section headings. Each record stores its source URL, SHA-256 file hash, and page numbers, with each article or section serving as the retrieval unit. The HCMUT corpus comprises 10 documents and 143 records (five documents are amendment-only, image-only base regulations are omitted, and decision numbers come from a web listing). The labour-law corpus comprises 10 documents and 458 records (Decree 145/2020 and unnumbered annexes are omitted, and texts reflect their promulgated versions without tracking later amendments). Neither corpus has been reviewed by an external legal or academic-affairs specialist.

\hdr{Retrieval pipeline (current D2 system).} At start-up, LuatCheck builds in-memory BM25 (over title and content) and word 1--3-gram TF-IDF indices and combines their rankings with Reciprocal Rank Fusion (RRF). The top 20 candidates are rescored by a local Vietnamese cross-encoder reranker to keep the top 5 sections (articles longer than 1{,}500 characters are scored by their best overlapping window). To prevent poor model query rewrites from hurting recall, the first search of every run combines the user's original question with the model's query.

\hdr{Preliminary vector-search experiment (toward D3).} For the D3 retrieval study, we also integrated an optional persistent index that pairs SQLite FTS5 keyword search with \texttt{EmbeddingGemma-2} dense embeddings (270M text parameters, \texttt{bfloat16} on Apple Metal, ${\approx}517$\,MB in RAM, $<6$\,MB on disk) into the codebase and demo UI. Testing this module on the two D2 corpora and an 818-query Vietnamese legal test set from Zalo AI (447 gold articles plus 553 BM25 hard negatives) showed three practical trade-offs:
\begin{itemize}
\item \textbf{Pure embedding search lags behind keyword search on legal text:} 768-d vector search alone reaches 52.9\% Recall@1 (66.1\% MRR@10) on the Zalo legal set, compared with 62.5\% (75.4\% MRR@10) for BM25+TF-IDF and 68.8\% (80.2\% MRR@10) for SQLite FTS5. Legal questions often depend on exact decree numbers, article IDs, or numeric thresholds, whereas dense embeddings pull in nearby clauses that share the same general topic.
\item \textbf{Truncating embeddings from 768-d to 128-d hurts accuracy without saving time:} Matryoshka 128-d truncation drops vector Recall@1 by 13.0 percentage points (to 40.0\%) and Recall@5 by 14.7 points (to 69.0\%), while query latency barely changes because the transformer still runs the same forward pass.
\item \textbf{Weighting keyword search higher in hybrid RRF gives the best recall:} An equal 50/50 RRF mix slightly lowers Recall@1 (to 67.0\%) because approximate vector matches can outrank an exact keyword hit. Weighting FTS5 at 0.75 and 768-d vectors at 0.25 keeps exact keyword matches on top while still helping on paraphrased questions, reaching 69.1\% Recall@1, 97.0\% Recall@5, and 80.9\% MRR@10 on the Zalo set (and 94.1--95.8\% MRR@10 on the D2 corpora).
\end{itemize}
