LuatCheck is one agent running a ReAct-style loop~\citep{yao2023react} over retrieval-augmented generation~\citep{lewis2020rag} (Figure~\ref{fig:arch}). Before any model call, input guardrails (regular-expression patterns, shared and per domain; no learned classifier) refuse obviously unsafe input, and the question is wrapped as untrusted text. At each step the controller chooses one action: search, read, answer, clarify or refuse. A search ranks records with BM25 and TF-IDF fused by reciprocal rank fusion (RRF), rescores the top 20 with a neural cross-encoder reranker and returns the best five.

An answer goes through the citation verifier. It checks in code that each cited record exists and was retrieved, that the quoted sentence appears in it, and that the claim's terms and numbers match the cited text. If the check fails, its report goes back to the controller for at most two repairs. This is external feedback rather than self-critique~\citep{huang2024selfcorrect}. The loop is bounded to 8 steps, 5 tool calls, 2 repairs and 180\,s. A backend or format failure ends the run as an execution error; it is never turned into an answer or a refusal.

There is one controller and no multi-agent coordination, which keeps permissions and budgets easy to inspect; the loop, tool registry, verifier and harness are custom Python (no external agent framework). The current system uses the 4B controller; a lighter configuration uses the 2B controller. Both are ternary-quantised Bonsai models\footnote{Bonsai 4B and 2B, ternary weights (about 2.1 bits per weight) in GGUF format, served locally by llama.cpp.} served by the same server. Everything in Figure~\ref{fig:arch} except the dashed boxes runs end to end. The two orange components, the reranker and the verifier, have on/off switches and are ablated in Section~\ref{sec:eval}. The dashed boxes are implemented but not used in any measurement. There is no code-execution tool and no external sender.
