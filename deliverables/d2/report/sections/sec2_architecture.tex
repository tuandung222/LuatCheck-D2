LuatCheck is a single-agent retrieval-augmented generation~\citep{lewis2020rag} system built around a bounded ReAct loop~\citep{yao2023react} (Figure~\ref{fig:arch}). In Phase~1 (offline), official PDFs are extracted, normalised to Unicode NFC, segmented at article/clause boundaries with SHA-256 and page provenance, and indexed into an in-memory BM25 and word 1--3-gram TF-IDF index. In Phase~2 (online), pre-model input guardrails (shared and per-domain regular-expression patterns) screen out unsafe requests and wrap the user input as untrusted text. At each step the controller selects one JSON-constrained action: \texttt{search}, \texttt{read}, \texttt{answer}, \texttt{clarify}, or \texttt{refuse}. A search ranks sections with BM25 and TF-IDF fused by reciprocal rank fusion (RRF), rescores the top 20 candidates with a neural cross-encoder reranker, and returns the top five clauses; a read action fetches the full section text from the normalized corpus.

\hdr{Rule-based citation verifier (L1 lexical heuristic, not a model or agent).} Every proposed answer goes through a deterministic Python heuristic module ($<2$\,ms on CPU, zero LLM or neural calls) that enforces three hard gates and one diagnostic check: (i)~\emph{retrieval provenance}: every cited \texttt{article\_id} must exist in the corpus and have been returned by \texttt{search} or \texttt{read\_document} during the current trial; (ii)~\emph{normalised verbatim/elided quote match}: after Unicode NFC, case and whitespace/line-wrap folding, every non-trivial segment ($\ge 12$ characters or $\ge 3$ words) of an elided quote (\texttt{...}) must appear verbatim and in order inside the cited record, with digit-boundary guards so \texttt{5} cannot match inside \texttt{15} or \texttt{3,5}; (iii)~\emph{claim-local number and unit match}: every numeric quantity and unit in an answer sentence must occur inside the $\le 300$-character source window that best matches the surrounding $\pm 8$ context words of that claim; and (iv)~\emph{content-word overlap}: if fewer than $50\%$ of a sentence's non-stopword tokens appear in the best source window, a soft diagnostic warning is logged. If any of the three hard gates fails, a structured tool report naming the failed rule and quoting the closest 170-character source span is returned to the controller for at most 2 repairs; if repairs are exhausted, the loop terminates as a refusal. This provides deterministic external feedback rather than LLM self-critique~\citep{huang2024selfcorrect}. The loop is bounded to 8 steps, 5 tool calls, 2 repairs and 180\,s. A backend or format failure terminates the run as an execution error rather than an answer or refusal.

Using a single controller without multi-agent coordination keeps tool permissions and step budgets directly inspectable; the control loop, tool registry, verifier, and evaluation harness are written in Python without an external agent framework. LuatCheck uses the 4B controller by default and supports a lighter 2B option; both are ternary-quantised Bonsai models\footnote{Bonsai 4B and 2B, ternary weights (about 2.1 bits per weight) in GGUF format, served locally by llama.cpp.} served by \texttt{llama.cpp}. All solid components in Figure~\ref{fig:arch} execute in the active pipeline; the orange modules (cross-encoder reranker and L1 citation verifier) are ablated in Section~\ref{sec:eval}, whereas the dashed modules are implemented in code but disabled during benchmark runs.
