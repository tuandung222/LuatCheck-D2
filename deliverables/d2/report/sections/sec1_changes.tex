\hdr{Scope and users.} The proposal (Application Track) targeted employees and HR staff asking labour-law questions. For this report we added a second corpus, the academic-affairs regulations of HCMUT used by students and advisers, to evaluate whether the same codebase serves an additional domain without code modifications. Prompts, tool names, and document-ID patterns are configured per domain.

Our current evaluation covers ten HCMUT academic documents and ten Vietnamese labour-law documents (the 2019 Labour Code, two related laws, six decrees, and one circular from 2020--2025), indexed from static public snapshots without tracking subsequent amendments. LuatCheck is a research prototype, does not provide legal advice, and has not yet been evaluated with end users.

Intended scenarios: a student looks up an academic rule and inspects the cited provision; an HR officer verifies a labour-law answer against the cited article; or a user pastes a document containing prompt-injection instructions, where the system must enforce its read-only tool boundary and either refuse or request clarification.

\hdr{Model, retrieval and evaluation adjustments.} Instead of the Qwen3 4B/8B controllers and 32B comparator in the proposal, LuatCheck uses two ternary-quantised local models (Bonsai 4B as default and Bonsai 2B as a lighter option) served by \texttt{llama.cpp} so that both the live demo and the evaluated controller run on a single 16\,GiB laptop. For retrieval, first-stage BM25 and word 1--3-gram TF-IDF fused by reciprocal rank fusion (RRF) feed a Vietnamese cross-encoder reranker (\texttt{top\_k=5}), with query anchoring on the user's original question on the first search; a dense vector index is implemented and scheduled for ablation in Week 46. Because the proposal's external held-out pair mapping could not be established, we constructed two hash-locked 50-question benchmarks and verified our offline LLM judge with a 60-item blind human audit.
