\section{Delta from Proposal and Project Status}

\hdr{Status Statement.} The LuatCheck system is currently \textbf{ON TRACK}. Between the D1 proposal in Week 2 and this Week 7 checkpoint, the core agent reasoning loop, tool execution layer, deterministic evidence verifier, and full evaluation and red-teaming harnesses have been implemented and run end-to-end on local hardware.

\hdr{Scope Modifications \& Technical Rationale.} In the D1 proposal, the team outlined a full roadmap including hybrid retrieval, deterministic citation checks (L1), semantic cross-encoders (reranking), and natural language inference (L2 NLI). At the Week 7 checkpoint, we made two conscious engineering decisions following the course's \textit{"learning through working"} and \textit{"fallback scope"} principles:
\begin{enumerate}[leftmargin=18pt,noitemsep]
    \item \textbf{Prioritization of L1 Deterministic Verification over L2 NLI:} In legal QA, deterministic provenance (verifying that the cited article exists in statutory law and was retrieved in the current session) eliminates 100\% of fabricated citations. Our initial measurements indicated that open-source cross-encoders on Vietnamese legal terminology introduce significant latency (over 1.8\,s per check) with negligible gain in precision over our calibrated token-overlap span support check. We therefore froze the L1 deterministic verifier as the mandatory floor and deferred L2 NLI to the Week 10 ablation.
    \item \textbf{Standardization on FastMCP (Model Context Protocol):} Rather than maintaining ad-hoc JSON function calling, we transitioned all tool definitions to the Model Context Protocol (MCP) standard via \texttt{FastMCP}. This strictly enforces tool permission boundaries (Read-Only vs. Reversible Write vs. Irreversible Egress) and provides an immediate bridge to external agent clients.
\end{enumerate}

The system operates as a finite-state machine controlled by a budgeted ReAct loop~\citep{yao2023react}. The agent chooses among five schema-constrained actions:
\begin{itemize}[leftmargin=14pt,noitemsep]
    \item \texttt{search\_law(query, top\_k=5)}: Queries statutory provisions using hybrid BM25 + dense retrieval with Reciprocal Rank Fusion ($k=60$).
    \item \texttt{get\_article(article\_id)}: Fetches the verbatim statutory text of a specific provision (e.g., \texttt{Dieu\_35}).
    \item \texttt{answer(content, citations)}: Formulates a structured legal response grounded in cited article IDs.
    \item \texttt{clarify(question)}: Inquires for missing case details if the legal threshold cannot be evaluated.
    \item \texttt{refuse(reason)}: Explicitly declines when the query demands illegal evasion or lacks supporting law.
\end{itemize}

\hdr{State Machine \& Agency Boundaries.} Agency is restricted strictly to deciding the sequence of retrieval and synthesizing legal answers under a strict budget cap ($\leq 5$ tool calls). If the agent invokes \texttt{answer}, execution passes to the deterministic verifier. If verification fails, a targeted repair prompt detailing the specific ungrounded statements is injected back into context. If the agent fails verification twice ($\leq 2$ repairs), the state machine deterministically overrides the model and transitions directly to \texttt{refuse}.

\section{Tools, MCP, and Memory Integration (R2, R3)}

\hdr{Tools and MCP Standard (R2).} The tool subsystem is exposed as a Model Context Protocol server implemented via \texttt{FastMCP}. We implement a strict three-tier permission model:
\begin{table}[H]
\centering
\small
\begin{tabularx}{\textwidth}{@{} l l l X @{}}
\toprule
\textbf{Tool Name} & \textbf{Permission Tier} & \textbf{Execution Mode} & \textbf{Security Policy} \\
\midrule
\texttt{search\_law} & Read-Only & Autonomous & Sublinear TF-IDF + BM25, bounded to statutory corpus. \\
\texttt{get\_article} & Read-Only & Autonomous & Verbatim article retrieval by standardized identifier. \\
\texttt{save\_case} & Reversible Write & Autonomous & Local episodic SQLite store with audit logging. \\
\texttt{send\_summary} & Irreversible Write & Human-in-the-Loop & Blocked by permission gate; requires explicit UI confirmation. \\
\bottomrule
\end{tabularx}
\caption{MCP Toolset and Permission Matrix in LuatCheck.}
\label{tab:tools}
\end{table}

\hdr{Dual-Tier Memory System (R3).} The memory architecture decouples ephemeral execution state from durable organizational knowledge:
\begin{itemize}[leftmargin=14pt,noitemsep]
    \item \textbf{Short-Term Memory (Case Ledger):} Implemented via Pydantic in-memory models. It tracks extracted facts, queries issued, retrieved article cache, and remaining tool/repair budgets. This ledger prevents context-window overflow and mitigates lost-in-the-middle phenomena~\citep{anthropic2024agents}.
    \item \textbf{Long-Term Episodic Store (SQLite):} Stores previously verified consultations. 
    \textit{Write Policy:} A case is committed \textit{only} if the terminal status is \texttt{answered} and has passed 100\% of L1 verification checks. Personal identifiers (PII) are cleansed.
    \textit{Retrieval Policy:} Lookup requires Jaccard/embedding similarity $\ge 0.85$ and a strict match against the statutory corpus version (\texttt{v2026.1}). All cached outputs undergo re-verification before presentation.
\end{itemize}

\section{Quantitative Evaluation and First Results (R5)}

\hdr{Experimental Setup.} We evaluate LuatCheck on 10 curated legal tasks derived from the VLQA dataset~\citep{vlqa2025} and Vietnamese Labor Code (Law No. 45/2019/QH14). Tasks span single-provision lookups, resignation notices, severance pay calculations, pregnancy protection, and disciplinary dismissal.
We benchmark two configurations across three independent random seeds (42, 123, 2026):
\begin{enumerate}[leftmargin=18pt,noitemsep]
    \item \textbf{Baseline (Verification OFF):} Standard single-pass RAG without deterministic citation or span checks.
    \item \textbf{LuatCheck (Verification ON):} Full ReAct loop with L1 Deterministic Verification and targeted repair.
\end{enumerate}

All experiments run entirely on local Apple Silicon hardware (Metal GPU acceleration) using quantized Qwen2.5-3B-Instruct.

\section{Threat Model v1 and Security Evaluation (R6)}

\hdr{Threat Model v1.} We identify three core assets: (1) legal advice integrity, (2) user personal data confidentiality under Vietnam PDPL 2025~\citep{vietnam2025pdpl}, and (3) external communication endpoints. The primary entry points are user query text, pasted documents (untrusted contracts), and poisoned retrieval shards.

\hdr{Security Findings \& Actionable Mitigation.} The initial security boundary successfully blocked 6 out of 10 attack cases (60\% Defense Rate). The 4 exploited cases revealed critical vulnerabilities in small models: (1) subtle roleplay leading to premature advice generation before verification, (2) nested indirect injection in complex markdown tables bypassing regex rules, and (3) poisoned retrieval text mimicking official decree syntax. 
\textit{Actionable mitigations scheduled for D3:} (i) hardening the system prompt with strict delimiter tagging, (ii) enforcing AST-level structural sanitization on pasted contracts, and (iii) deploying a dedicated lightweight semantic classifier to intercept injection payloads before the ReAct loop executes. Importantly, even when the agent was misled to formulate an egress summary, the hard permission gate on \texttt{send\_summary} unconditionally required human interactive confirmation, preventing any silent exfiltration.
