\section{Changes from the Proposal}
LuatCheck targets employees and SME HR staff who need an understandable answer linked to the provisions loaded into a local knowledge base. It covers a frozen original-2019 Vietnamese labour-law corpus, not all legal advice. Results produced by earlier versions that substituted rule-based answers for model output are excluded from all conclusions.

\hdr{Application scenarios.} (1) An employee checks a probation or wage condition and inspects the cited article. (2) SME HR staff ask an employment question using a local model; the corpus scope and privacy limitations still apply. (3) A careless or malicious user pastes a contract with injected instructions or requests evasion of a legal duty; the system should enforce its tool boundary and ask for clarification or refuse as appropriate. These are intended scenarios, not completed user-study evidence.

\section{Implemented Architecture (R1)}
The application currently uses one agent. Its ReAct-style loop~\citep{yao2023react} calls a Python tool registry directly; the separate MCP server is not a transport used by the main loop. No multi-agent coordination is claimed.
This pattern permits additional source lookup and bounded repair after a failed check. A single controller keeps tool permissions and budgets inspectable on one local machine. Its benefit over the simpler OFF configuration remains an empirical question.

\section{Memory and Knowledge Sources (R3)}
\hdr{Short-term state.} The ledger stores the question, issued searches, retrieved IDs/text, budgets, action/verification events and native-call telemetry. It supports task inspection, not another autonomous agent.

\hdr{Episodic memory.} The agent writes answers following its configured verification gate and native-call evidence. Query, answer and citation strings undergo supported-pattern filtering. Reuse requires matching index version, native-origin metadata and similarity threshold 0.85. Legacy records without native-origin metadata are skipped; records are retained, not silently relabelled. The similarity combines TF-IDF cosine and Jaccard. Cached answers are rechecked in the selected verification mode. D2 experiments disable memory reads/writes. The demo configuration also disables answer reuse while still storing verified answers: matching considers only the question text, not a pasted document or case facts, so a question that differs in one legally decisive detail could be served another case's answer; re-running L1 on the cached answer does not establish that it applies. Pattern filtering is incomplete data minimisation, not proof of legal compliance or removal of all personal data. Native-origin metadata assumes trusted code/storage; it is not a signed backend attestation.

\hdr{Knowledge corpus.} The current retrieval corpus contains all \textbf{220 numbered articles} of the original Labour Code 45/2019/QH14 in the official Gazette dated 26 December 2019~\citep{bll2019gazette}. It is not a consolidated representation of current 2026 law. The 94-page text PDF, SHA-256 manifest, extraction script and page-level text are preserved in \code{docs/materials/benchmark-sources}. Each retrieval record has its source URL, source-PDF hash and page numbers. Extraction removes running Gazette headers, normalises Unicode/whitespace and segments article headings; it does not rewrite legal provisions. Automated checks establish unique coverage of articles 1--220 and exact containment of the selected reference excerpts.

BM25 indexes titles/content; TF-IDF uses word n-grams 1--3. RRF uses $k=60$. Each search component considers twice the requested result count; the final count is capped at five. No neural embedding is silently substituted. Source checking and task curation were assisted by OpenAI Codex; \pending{a legal expert has not yet certified the corpus extraction, task conditions or gold answers.}

\section{Evaluation Set and Initial Results (R5)}
\hdr{Benchmark provenance and selection.}
\code{evaluation/benchmarks/bll2019_v1/tasks.json} contains ten purposively selected, source-grounded local tasks: seven single-provision questions, two multi-article synthesis questions and one foreign-jurisdiction refusal. The nine answerable tasks have frozen reference answers and exact source excerpts with Gazette page numbers. The original drafts were revised before main outputs: an inconsistent contract-duration scenario was removed, disciplinary dismissal was distinguished from unlawful unilateral termination, notice-period exceptions were stated, and the explicit contract-guarantee deposit question was corrected to be answerable under Article 17. No task or gold is changed to fit model output.

These are \textbf{local curated tasks, not a verified public VLQA split}. The legacy VLQA record mapping could not be established; ALQAC file access was restricted and was not bypassed. The source-review manifest names the AI reviewer and marks expert review pending. This small development set does not establish broad or held-out legal performance. The proposal's final targets of twenty end-to-end tasks and 200 held-out retrieval pairs remain separate work.

\hdr{Native configurations and controls.}
OFF and L1 ON use the same Qwen2.5:3B Q4\_K\_M model, prompt, corpus, budgets and explicit BM25/TF-IDF retrieval. OFF removes verification; ON checks citation existence, retrieved provenance, verbatim-quote containment, lexical overlap and quantities, then permits bounded repair. Optional NLI requires a real native model and is excluded from this comparison. There are no response substitutes, injected stand-in components or answer-cache hits. Episodic memory is disabled by a real configuration flag, rather than replacing methods.

The first environment is the user's Apple M4, 10 CPU cores and 16 GiB unified memory. Ollama 0.34.4 reports Metal placement, 8,192 context tokens and model allocation in GPU memory. Runs are sequential. Seeds 42, 123 and 2026 are passed to the native API; OFF/ON order alternates by task. Three seeds repeat ten tasks, not thirty independent legal questions. Native prefix caching is backend behaviour; response-cache reuse is disabled. Some software checks and report compilations ran on the same Mac during collection; no second model inference workload was run concurrently. Timings are observations of this desktop environment, not isolated throughput or causal speedup measurements.

\hdr{Measured metrics and semantic judging.}
Retrieval recall counts the fraction of gold IDs recovered; hit and MRR remain distinct. Trajectory Recall/Hit@5 use the first five unique IDs accumulated during the tool trace; MRR uses the first relevant ID in the complete ordered unique trajectory. Neither is a separate held-out retrieval test. Citation-ID precision/recall use the reference ID set and are aggregated only over answerable trials. Empty-gold foreign-scope rows have no applicable source-ID recall; their raw legacy convention is excluded. These do not establish whether a cited provision entails a claim. Gold ID sets may also omit a valid alternative source; semantic review must inspect the actual text rather than equate ID mismatch with a wrong answer. Separating answer correctness from citation support follows the evaluation distinction in ALCE~\citep{gao2023alce}.

Latency includes the agent loop; tokens come from native usage fields, including additional repairs. Missing usage stays unknown. Model service-hours sum backend request durations on the Metal-backed model; they are \emph{not} a hardware GPU-active measurement. A local API fee is not a claim of free compute.

Task correctness, completeness, claim support and the appropriateness of refusal/clarification require semantic review. The prepared judge protocol supplies question, frozen reference/rubric, source articles and a blinded candidate answer; it excludes OFF/ON and L1 acceptance. Judge bias and agreement with human ratings must be checked rather than assumed~\citep{zheng2023judge}. The group selected DeepSeek V4.1 Flash. The Qualgo gateway exposes \code{deepseek/deepseek-v4-flash}, identifies the provider as DeepSeek, and returns that same model ID. Official DeepSeek documentation maps the legacy upstream alias to V4.1-Flash-1017~\citep{deepseek2026api}; this mutable gateway route is not an independently attested or pinned model revision. The judge uses thinking enabled, high reasoning effort, an 8,192-token completion cap, JSON output and at most two initial attempts per output, with a separately disclosed streamed recovery for invalid judgments; no seed or effective sampling temperature is claimed. Strict success requires appropriate behaviour, correctness 2/2, completeness 2/2 and every factual claim supported. The gateway receives curated benchmark questions, answers and statutory sources separately from local controller inference. Full prompts, raw responses, model IDs and usage are retained. \textbf{Planned human check:} group members label the 12-output stratified audit sample blind to the judge verdict on Saturday 24 October 2026; agreement and Cohen's kappa against the judge's strict-success label will then be reported. \pending{Human audit scheduled for 24 October; not yet performed.}

\hdr{Controller diagnostic: task difficulty or model capacity?}
To separate the two, the same ten tasks were rerun once (seed 42, OFF and ON) with only the controller model changed: \code{openai/gpt-5.5} through the API gateway (reasoning effort low, 2,048-token cap) and Ternary Bonsai 2 4B on the Mac (MLX, schema-constrained decoding, 768-token cap). Corpus, retrieval, budgets and L1 are unchanged; both diagnostic runs use the post-collection prompt revision described under Reproduction, so the Qwen column (seed-42 trials of the main run, original prompt) is not an exact same-prompt baseline (Table~\ref{tab:diag}). GPT-5.5 had no execution errors, cited exactly the gold article IDs and reached trajectory Recall@5 of 1.0. An AI inspection against the frozen references (not a human label and not the frozen judge protocol) found its 18 answers consistent with the reference answers and both foreign-scope trials appropriately refused. The tasks, corpus and loop are therefore solvable. We treat controller capacity as the leading hypothesis for the failures in Table~\ref{tab:errors}, not an established cause: the diagnostic runs also differ in prompt revision, decoding and output cap, and use one seed. Bonsai 2 4B sits between the two: by the same AI inspection, 12 of 20 trials were consistent with the reference, it read the wrong provision on three tasks (absence, unlawful termination, deposit), and both trials of the two-provision notice/severance task exceeded the 60-second per-call timeout after the context grew to about 10,000 tokens. Unlike Ollama's 8,192-token window, \code{mlx_vlm.server} does not truncate the context; one recorded call reached 9,606 input tokens. On the deposit task, L1 rejected an answer whose conclusion was right but whose citation was wrong, and the repair ended in a refusal.
L1 forced six repairs on GPT-5.5 answers that were then accepted, mostly because a paraphrased \code{exact_quote} was not verbatim; the quote check therefore also rejects acceptable answers. Caveats: one seed; the gateway cached byte-identical requests (20 of 48 response IDs recur), so OFF and ON are not independent samples and the second trial's latency is not model latency; the gateway route is not a pinned revision. For the demo model, the same Bonsai 2 2B weights were also run on both runtimes after the tool change: across the 20 diagnostic trials the \code{llama.cpp} GGUF build took 197\,s in total against 427\,s for MLX (median 7.6 vs 13.7\,s per trial), with no execution errors against two, and its server used about 0.7\,GB against a 6.6\,GB peak; their answers differ because sampling differs between runtimes, so this is a speed and stability comparison only. The 2B demo model is also the least accurate controller in Table~\ref{tab:diag} (11/20 expected actions, citation-ID precision and recall 0.22), so the demo illustrates the loop, not answer quality. These diagnostic runs (\code{evaluation/runs/*-diag-v1}) are not main results; the table is regenerated by \code{evaluation.render_diagnostic_table}.

\hdr{Pilot findings and limitations.}
The first pilot retained eight native trials. The controller sometimes asked users for statutory information hidden beyond a 300-character snippet; it also produced a legally wrong synthesis that passed L1. Search responses were changed to expose truncation explicitly and the prompt now requires reading the full article instead of treating a snippet's omission as missing user facts. A second four-trial interface pilot retained all outputs, including an unnecessary clarification. Neither pilot is merged into main results or presented as held-out validation.

A concrete first-pilot failure conflated the notice period with service time used for severance in Article 46. This illustrates why lexical acceptance cannot be called legal correctness. Main failures and raw native responses, including parse errors, truncation and deadlines, remain in the result artifact. There is no statistically established superiority claim from this small set. The saved backend log also records context shifting in some calls at the configured 8,192-token limit. Full request text is retained, but that does not establish that all earlier evidence remained in the model's active context. Reducing duplicate observation fields or increasing context requires a separately versioned rerun, rather than revising this frozen batch.

Ten of the twelve trials had already used all five tool calls, and the failing requests carried 5,640--8,112 input tokens against an 8,192-token context. \code{BLL19-04-ABSENCE} failed in all six trials. Planned mitigations for a separately versioned rerun are shorter observations, schema-constrained decoding and a higher output cap.

\hdr{Observed main-run failure (AI inspection, not an aggregate judge score).}
For \code{BLL19-10-FOREIGN_SCOPE}, seed 123, ON answered that California overtime was limited to 200 hours per year, citing Vietnam's Article 107; the ledger marked the output \code{verified=true}. The configured corpus contains only the original Vietnamese statute and supplies no California authority. This is a concrete jurisdiction/support failure that the implemented L1 checks did not reject. Its native output is preserved in \code{evaluation/runs/bll2019-main-v2/runs.jsonl}. Independent LLM-judge estimates are reported separately; this qualitative inspection is not a human correctness label.

\hdr{Reproduction.}
The run directory stores frozen task/corpus hashes, environment metadata and a source snapshot. The main-collection table is regenerated from the stored trials by \code{evaluation.render_native_table} (and the summary by \code{evaluation.analyze_native}), each taking \code{--run-dir}, \code{--tasks} and \code{--output}; a new collection requires \code{python -m evaluation.run_eval --execute} with a fresh output directory (full commands in \code{report_d2/D2_EXPERIMENT_PLAN.md}). After collection, the source was revised without rerunning: the system prompt now names only the labour-law corpus and uses an ID placeholder instead of example article IDs (one main trial had copied the example ID); a keyword-based actor-title rule was removed from L1 (it never triggered in any pilot or main trial); and unreachable fallback branches were replaced by explicit errors. Later, tool observations were compacted: duplicated fields were removed, search returns the two clauses that best match the query (with their lead-in) instead of the first 300 characters, and a repeated query or article read returns a short notice. Replaying the main run's own tool calls offline, observation text shrinks by 60\% and the reference excerpt appears in the search snippet for 66 instead of 36 of 110 gold-article hits (\code{evaluation.measure_tool_observations}). The GPT-5.5 and Bonsai 4B diagnostics predate this change.
